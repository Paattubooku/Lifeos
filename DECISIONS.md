- 2026-11-23 · design · Designs reconciled with the PRD; see `design/DESIGN_NOTES.md` (PRD v1.2).

- 2026-11-22 · F00 · App identifiers `app.lifeos.ptr` (iOS bundle id / Android package) are placeholders until PTR picks real ones before the first EAS build.
- 2026-11-22 · F01 · **`client_id` + `deleted_at` on every user table**, not only log tables. Plans (routine blocks, dishes, program) are also edited offline through the sync queue (F02), so they need idempotent upserts and soft delete too. `client_id` defaults to a random uuid so server-side inserts (seed, Edge Functions) don't need one.
- 2026-11-22 · F01 · **Log → plan references are plain uuids, no FK** (`block_log.block_id`, `food_log.dish_id`, `session_log.workout_day_id`, …), as PRD §5 writes them. Editing or deleting a plan row never cascades into past logs (PRD §1.3). Plan → plan links (`routine_block.template_id`, `meal_item.dish_id`, …) are FKs with `on delete cascade`.
- 2026-11-22 · F01 · **One RLS policy per table**: `for all to authenticated using/with check (user_id = (select auth.uid()))`; anon gets nothing. Views are `security_invoker`, so they obey the caller's RLS (without it a view would leak every user's rows; `supabase/tests/rls.sql` checks this).
- 2026-11-22 · F01 · **`seed_defaults()` is idempotent per section** (profile, routine, meal plan, program, expense categories): a section is created only if the user has no rows for it, soft-deleted rows included, so templates PTR deletes are never resurrected. Security invoker + advisory lock against two devices signing in at once. The app calls it after every sign-in and retries on next launch if it failed.
- 2026-11-22 · F01 · **Seed details the PRD left open**: block durations (wake 10, water 30 so "500 ml before 05:40" works, workout 60, meals 30/15, pack lunch 15, phone away 30, lights out 15 min); Rest day = Workday minus the workout block; program `start_date` = first Monday on/after the IST logical day of the first sign-in (F03 resets it at onboarding); timed exercises store the seconds range in `rep_min`/`rep_max` with `duration_sec` = max (Plank 30–45 s); "max" reps = both null (Push-up); circuit stations have 0 s rest except 60 s after the last; dish `shopping_items` are empty until F10; expense categories are the design's 6 + Income (A14) with PRD F18 budgets; `expense_skipped.classification` also allows `otp` (A16).
- 2026-11-22 · F01 · **`v_daily_summary.kcal` is food only**; coffee (20 kcal each) is added by the app from `coffee_count`, so the coffee kcal constant isn't duplicated in SQL. `v_weekly_rollup.weight_change` = last 7-day average in the week minus the last one before it.
- 2026-11-22 · F01 · **SQL tests are plain SQL in a rolled-back transaction**, not pgTAP, so they run on a local Postgres (`npm run test:db`, no Docker), in the Supabase SQL editor, or via psql against the real project without leaving data behind.
- 2026-11-22 · F01 · **Types generated locally** (`npm run gen:types`: migrate a throwaway Postgres, introspect, emit the `supabase gen types` shape) because this environment has no Docker and no linked project. Switch to the official `npx supabase gen types typescript --linked` once the project is linked; the shape is the same.
- 2026-11-22 · F01 · **Session storage = chunked expo-secure-store**: a Supabase session is >2 KB (SecureStore's per-value limit), so it's split into 1.8 KB pieces. Storage key `lifeos-auth`.
- 2026-11-22 · F01 · **Offline launch**: if refreshing an expired token fails with a network error, the user stays signed in from the stored session (`auth.offline = true`) and the app retries when it returns to the foreground. A non-network failure (revoked token) signs out.
- 2026-11-22 · F01 · **Sign-up** only when `__DEV__` and `EXPO_PUBLIC_ENABLE_SIGNUP=1`. In production the account is created once (dashboard or dev flag) and sign-ups are then disabled in the Supabase project.
- 2026-11-22 · F01 · **Sign out on More → Account** (local scope: forgets this phone's session even offline). PRD puts sign-out in F23 Settings; it's needed now to test sign-in and switch accounts.
- 2026-11-22 · F01 · The app-wide store singleton moved to `src/store/root.ts` (imported only by `app/_layout.tsx`) so tests never start redux-persist timers. Changes F00 code; needed to fix a Jest open-handle leak.

- 2026-11-23 · F02 · **Queue = its own persisted Redux slice** (`persist:lifeos-sync`, MMKV / AsyncStorage) so the UI can select pending rows and counts directly; only `queue`, `dead`, `lastSyncedAt` are saved.

- 2026-11-23 · F02 · **Worker is skipped while NetInfo says offline** (no attempts burned); `lastSyncedAt` is set after a run with no failures.
- 2026-11-23 · F02 · **Soft delete** stores the moment of deletion in the queued row and pushes that as `deleted_at`.
